pairing: security and reliability fixes:

**Behaviour change:** a wake now wraps the same policy connect as every other Day-2 connect, and failure text no longer prints raw URLs, hints, codes or input. Nothing about pairing URIs, route sets or stored routes changed on the wire.

- **Wake parity:** every surface honours `pre_wake`: the CLI, the C ABI (and so Go, Swift and Kotlin), Python and Node. The connect a wake runs is the route-aware policy connect, so a woken session sends `route_seq`, ingests `0x0C` route sets and accepts a recovery URI (`dial --wake-url ... --pairing-uri`). No surface keeps a separate pre-dial. A hint is sent, and the connect retried, only for `AttemptError::is_wakeable_miss`: an uncommitted attempt whose failures are I/O, timeout, closed, or a typed relay `offline` refusal (`RuntimeError::RelayOffline`, formerly matched by message text). A committed attempt, a key, pin or grant failure, an admission refusal and a protocol failure end the dial. A Day-2 connect that failed after establishing a session now reports `committed: true`.
- **Redaction:** CLI diagnostics, `tendril_last_error`, and Python, Node and browser errors never echo raw URLs, hints, relay URLs, codes or input. Shared helpers in `tendril_runtime::redact` print `scheme://host[:port]` or `<redacted>`. Pairing URI parse errors name only the failure. JSON errors report category, line and column. Dropped endpoints print redacted. Closed bypasses: backslash and `@` in a path, query or fragment, punctuation in a host, prefixed codes, percent-escaped hosts, and text glued to a URL. A hint without `://` keeps its prefix only for `direct`, `local`, `overlay`, `relay`, `broker` and `p2p`. WebSocket and relay URL errors pass through the text scrubber. A multibyte character next to a URL no longer panics the scrubber.
- **Lock order:** `RouteAnnouncer::issue_pairing_uri` held the pairing manager while it published under the roster file lock, and a store-backed pairing claim takes the file lock and then the manager, so a QR refresh during a pairing could deadlock. It now takes `&Mutex<PairingManager>` and locks it after the store I/O. The order is store lock, roster file lock, pairing manager, in-memory roster, and client route ingest runs off the session loop. See the SDK embedder note in [FFI ABI and cross-language bindings](../../reference/ffi-and-bindings.md#lock-order-for-sdk-embedders).
- **Operator iroh:** relay host names of an explicit `iroh://` endpoint are resolved once, screened against the blocked set and pinned for the dial, and the dialer keeps the pins for every dial. A resolver bypass or a rebinding answer cannot steer the connect. `--p2p-pkarr` and `--no-pkarr` (`p2p_pkarr` in transport configuration) reach operator iroh dials only; URI and stored hints keep lookup off.
- **Revocation persistence:** CRL evidence a live session accepted survives route writes, roster reloads and failed sessions. A CRL that revokes the peer is persisted before `PeerRevoked` is returned, trust-anchor CRLs are merged, Day-2 connects always install client ingest, and evidence stays queued after a failed write or a transient store error. Queued route sets are drained before a write error is returned.
- **Route configuration:** Go, Swift and Kotlin `configureRoutes` merge into the last full transport configuration the binding sent instead of resetting other keys. A failed call leaves the cache unchanged, and Go, Swift and Kotlin clear it on close. In Go the two list fields of `RouteConfig` are `*[]string` (`nil` keeps the list, an empty slice clears it), and Swift `startPathMonitoring` throws on a closed endpoint.
- **Web and WASM:** errors carry a stable `code` and candidates are ranked by it. `clearPeerRoutes` defaults to the `operator` source. The client locks when authenticated evidence cannot be persisted: every open session fails and closes, and later roster and group calls reject. An explicit `pair` endpoint that is a `/v2/relay` URL is rejected. `insecure_ws` is a reported skip reason, and a stored off-loopback `ws://` route is skipped with it before any dial. Browser `iroh://` hint dials (URI hints and stored `signed` or `committed` routes) attach no address lookup and use the relays of `p2pRelayUrls` or the Default relay map; stored `operator` iroh routes keep their `relay=`. The pairing result field is `routes_reason`, as on the other bindings, and a paired host is stored under the URI host name.
- **Python and Node:** an empty `code` option is rejected before any dial, every Node transport key has a camelCase alias, and Node route methods return Promises. The method inventory is in [FFI ABI and cross-language bindings](../../reference/ffi-and-bindings.md#python-and-node-method-inventory).
- **Errors:** a Wire v2 initiator that waits too long for a process-wide Argon2id permit fails the rung with `argon2id permit wait timed out`, uncommitted, and the next rung is tried.
