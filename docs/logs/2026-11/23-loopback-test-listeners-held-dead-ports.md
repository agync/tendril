Loopback test listeners: held dead ports and foreign requests ignored:

- **Dead ports (`crates/tendril-runtime/tests/provider_contract.rs`):** the four tests that dial an unreachable loopback address used to bind a port, drop it, and dial it. The iroh relay clients keep retrying such a URL for the whole test, and a parallel test can bind the freed port in the meantime. A `DeadPort` guard now holds the client end of an established loopback connection and hands out its local port. Nothing listens there, so dials are refused at once, and ordinary `bind(0)` allocation cannot return the port while the test runs. On macOS an explicit `SO_REUSEADDR` rebind of that exact port can still succeed; the guard prevents ephemeral allocation, not that. The guard keeps only the accepted stream whose peer is its own client, because a host process that probes new loopback listeners can connect first; dropping the seed listener with the real peer still queued would reset the client and free the port. Setup polls a nonblocking accept under a 5-second deadline and panics clearly if the client never arrives. `dead_port_guard_ignores_a_foreign_connection_that_arrives_first` connects a stray before the client. A socket that is only bound is not enough: macOS drops SYNs to it without a reset, so the dial hangs until the connect timeout (about 8 seconds). `dead_port_guard_refuses_dials_and_holds_the_port` checks for an immediate refusal under a 2-second deadline.
- **Stream pairing (`crates/tendril-runtime/tests/provider_contract.rs`):** any process on the host can connect to a loopback listener. For example, a local service-discovery daemon sends `GET /` to every new listening port about every 45 seconds. `open_pair` took the first accepted stream as the dialed one. A stray connection therefore shifted every later pairing in the test, and the direct and overlay contract tests failed with `BadPreambleMagic` or `Closed` at the session accept (9 failures in 200 runs, each during such a probe). The dialer now sends a random 16-byte tag. Each accepted stream is checked in its own task, with one deadline over the whole tag read, and only the stream carrying the tag is kept. `open_pair_skips_foreign_connections_without_waiting_on_silent_ones` covers an HTTP stray and a silent stray. Production accept paths already drop such streams.
- **Foreign requests (`bindings/web/test/security.test.mjs`):** the fake relay upstream in the SEC-23/27 and PRIV-08 tests counted every connection, so such a probe failed `expected 0, actual 2`. The upstream now counts only requests for a relay path or with the test's random WebSocket key, and lists ignored requests in assertion messages. It also captures every request head on a counted connection, so a proxy that forwards the upgrade twice on one socket fails the exact-count assertions; a witness test writes two heads on one socket, in one write and in two.
