# 0005 Apple Secure Enclave custody, wake transport, and extensions

## Context

Tendril's Swift binding (`bindings/swift`) previously sealed device state in `TendrilKeychainStore` using an extractable symmetric key (`kSecClassGenericPassword`, envelope `0x01`), shipped only as a local subpath SwiftPM package requiring a full Rust/Cargo toolchain, and left iOS background extension constraints (App Group Keychain access groups, Data Protection Class C on shared state directories, `0xdead10cc` SQLite/file-lock suspension traps, and the ~24 MiB Notification Service Extension Jetsam ceiling) unaddressed. Meanwhile, `HttpWakeProvider` in `tendril-runtime` formatted silent APNs JSON over HTTP/1.1 with an empty TLS root certificate store on default construction and per-dial instantiations that discarded `WakeCoalescer` state.

After freezing [ADR 0004](0004-hybrid-post-quantum-v1.md) (`Ed25519 || ML-DSA-65` hybrid identities and `Noise_XXhfs`), three architectural choices for Apple platforms and wake delivery were locked on 2026-11-25 (`D1=B`, `D2=B`, `D3=2`) alongside six implementation invariants (`S1` through `S6`).

## Decision

Keep `tendril-core` as the sole protocol and cryptographic trust boundary (`unsafe_code = "forbid"` in `tendril-core`, `tendril-runtime`, `tendril-cli`, `tendril-relay`, and `tendril-wasm`, isolating C ABI `unsafe` strictly inside `crates/tendril-ffi`) while adopting the following decisions across custody, packaging, extension runtime lifecycle, and APNs wake delivery.

> **Rollout scope:** Wave 1 establishes the core/runtime custody foundation (`ExternalMlDsaSigner` in `tendril-core`, `PersistedIdentity` `version: 2` in `tendril-runtime::store`, and HTTP/2 APNs wake primitives in `tendril-runtime::wake`). All downstream C ABI (`crates/tendril-ffi`), Swift Keychain/SEP/extension wrappers (`bindings/swift`), root SwiftPM packaging (`Package.swift`), and release-workflow symbols recorded below are normative design targets across Waves 1-4.

### 1. Tier 1 + Tier 2 Secure Enclave custody (`D1 = B`)

Combine immediate hardware key-wrapping on current Apple OS releases (Tier 1) with hardware-bound post-quantum ML-DSA-65 co-signing on Apple Silicon OS 26+ (Tier 2):

- **Tier 1 (`iOS 16+ / macOS 13+`, design target for `bindings/swift` in Wave 2): Secure Enclave P-256 ECIES key-wrapping (`formatVersion = 0x02`).** When Secure Enclave is available and custody policy is `.secureEnclaveOrKeychain` or `.secureEnclaveRequired`, `TendrilKeychainStore` generates a `SecureEnclave.P256.KeyAgreement.PrivateKey` (defaulting `SecAccessControlCreateFlags` strictly to `[.privateKeyUsage]`, omitting interactive biometry flags that trigger `errSecInteractionNotAllowed` in background extensions), seals identity state using ephemeral P-256 ECDH + HKDF-SHA256 (`"tendril.se.wrap.v1"`) + AES-GCM (`"tendril.state.v2\0" || aad`), and stores no persistent extractable symmetric master key while retaining read compatibility with legacy `0x01` envelopes.
- **Tier 2 (`iOS 26+ / macOS 26+` on A14+/M1+): Hardware ML-DSA-65 co-signing via `ExternalMlDsaSigner`.** Because `ML-KEM-768` handshake keys are ephemeral and `ML-DSA-65` is the post-quantum half of `HybridSigningPublicKey` (`Ed25519 || ML-DSA-65`), Tier 2 binds **only the ML-DSA-65 half** inside Secure Enclave hardware (`SecureEnclave.MLDSA65.PrivateKey`), while the Ed25519 half (`signing_seed_b64`, also used for untrusted relay control authentication via `EndpointIdentity::mint_relay_ticket`) remains persisted inside Tier 1 SEP-wrapped `identity.sealed` because Secure Enclave hardware cannot execute Ed25519:
  - **Core custody seam (`tendril-core`, implemented in Wave 1B):** `tendril-core` introduces the `ExternalMlDsaSigner` trait (`Send + Sync`), `SigningKeypair::from_ed25519_and_external`, and custody-safe `mldsa_seed_bytes_opt()` / `is_external_mldsa()` accessors. `SigningKeypair::sign` always calls `self.public.verify(message, &out)?` on external ML-DSA-65 signatures before returning `Ok(out)` so faulted, mismatched, or wrong-context outputs fail closed immediately. `sign_deterministic` rejects external keypairs with `CoreError::ProtocolViolation`, and `EndpointIdentity::rotate` rejects `External -> Software` custody downgrades with `CoreError::ProtocolViolation` while permitting `Software -> External` and `External -> External` rotations.
  - **Identity persistence `version: 2` (`tendril-runtime::store`, implemented in Wave 1B):** `PersistedIdentity` emits `version: 1` (`pq_signing_seed_b64` present, external fields absent) for software identities and `version: 2` (`pq_signing_seed_b64` omitted, `pq_signing_custody: "external_mldsa65"`, `pq_signing_pub_b64` 1952-byte ML-DSA-65 key; `signing_seed_b64` still holds the Ed25519 half inside the sealed blob) for external identities. `deserialize_identity_json_with_signer` and `StateStore::load_or_generate_identity_with_signer` enforce strict mutual exclusion between v1 and v2 fields, reject attaching an unused external signer to v1, require a matching signer verified via constant-time `ct_eq` for v2, and keep `deserialize_identity_json` failing closed on v2.
  - **C ABI and Swift provider (normative design target, Wave 2):** `crates/tendril-ffi` will expose `TendrilMlDsa65Signer` (`public_key`, `public_key_len`, `sign`, `drop_ctx`) via `tendril_endpoint_new_sealed_with_options`, and `bindings/swift` will wrap `SecureEnclave.MLDSA65.PrivateKey` behind `TendrilMlDsa65Provider` when OS and hardware support it.

### 2. Remote-consumable SwiftPM binary package (`D2 = B`, normative design target, Wave 4)

Ship a root `Package.swift` (`swift-tools-version: 5.9`, `.macOS(.v13)`, `.iOS(.v16)`) backed by a deterministic release `TendrilFFI.xcframework` zip (`scripts/build-xcframework.sh`, exporting `module CTendril [system]` over `tendril.h` + embedded static libraries to match the local `module CTendril [system]` over `shim.h` + `link "tendril_ffi"` and the identical `crates/tendril-ffi/include/tendril.h` C ABI surface, `--locked --release` builds for `aarch64-apple-darwin`, `aarch64-apple-ios`, `aarch64-apple-ios-sim`, stripped debug info, `ZERO_AR_DATE=1`, and canonical Python `zipfile` timestamps/permissions). Root `Package.swift` uses `.binaryTarget` (initialized with an all-zero placeholder checksum prior to the first tagged release and updated with the verified `swift package compute-checksum` SHA-256 on release PRs, while tag workflows verify the checksum against the rebuilt archive). Local development and CI preserve `TENDRIL_LOCAL_FFI=1` and restrict `.unsafeFlags` strictly to `TENDRIL_LOCAL_FFI=1`.

### 3. Direct HTTP/2 APNs and visible `mutable-content: 1` push (`D3 = 2`, normative design target across Waves 1A and 2)

Support direct HTTP/2 APNs delivery in Rust alongside webhook, UnifiedPush, FCM, and gateway APNs adapters, and allow operators to pair silent background wakes (`ApnsPushMode::Background`, `apns-push-type: background`, `apns-priority: 5`) with visible fallback alerts (`ApnsPushMode::MutableAlert`, `apns-push-type: alert`, `apns-priority: 10`, `mutable-content: 1`, `alert.loc-key`) so iOS Notification Service Extensions (NSE) can wake reliably under background-push throttling without exposing dynamic text, format args, or peer identities to Apple gateways.

### 4. Invariants `S1` through `S6` (normative across Waves 1-4)

| Area | Target Wave(s) | Invariant |
|---|---|---|
| `S1` Secure Enclave custody | Wave 1B (`core`/`store`), Wave 2 (`ffi`/`swift`) | Default SEP access control is `[.privateKeyUsage]` only; Tier 2 binds only ML-DSA-65 inside SEP while Ed25519 (`signing_seed_b64` / `mint_relay_ticket`) stays inside Tier 1 SEP-wrapped `identity.sealed`; external ML-DSA-65 outputs always self-verify against `HybridSigningPublicKey` before leaving `SigningKeypair::sign`; `EndpointIdentity::rotate` forbids `External -> Software` downgrades; `PersistedIdentity` v1/v2 fields are strictly mutually exclusive. |
| `S2` Remote SwiftPM distribution | Wave 4 | `CTendril` exports the same module name (`module CTendril [system]`) and `tendril.h` C ABI surface across local (`shim.h` + `link "tendril_ffi"`) and XCFramework (`tendril.h` + embedded static library) builds; root `Package.swift` uses `.binaryTarget` (initialized with an all-zero placeholder checksum prior to the first tagged release and updated with the verified `swift package compute-checksum` SHA-256 on release PRs) and restricts `.unsafeFlags` strictly to `TENDRIL_LOCAL_FFI=1`. |
| `S3` App Group and Keychain hardening | Wave 2 (`ffi`), Wave 3 (`swift`) | `kSecAttrAccessGroup` and macOS Data Protection Keychain (`kSecUseDataProtectionKeychain`) isolate shared extension credentials while keeping unentitled local CLI tests functional; iOS App Group state directories and files enforce `FileProtectionType.completeUntilFirstUserAuthentication` (Class C); state-mutating FFI calls run under `performExpiringActivity` (`0xdead10cc` protection); `client_only: true` forbids listener/server operations and skips the 60 s `RouteAnnouncer` timer. |
| `S4` Background extension runtime | Wave 2 (`ffi`), Wave 3 (`swift`) | `runtime_profile: "extension"` limits Tokio to 1 worker thread, 2 max blocking threads, and 512 KiB stacks inside iOS NSE memory budgets; `tendril_verify_wake_tag` delegates constant-time epoch window checking (`verify_epoch_wake_tag_window`) to Rust; `TendrilWakeProcessor` and `TendrilLocalPushSession` (`NEAppPushProvider`) mandate non-empty `requiredCap` and enforce `session.authorize(requiredCap)` before surfacing frames, while `TendrilBackgroundSync` wraps `BGTask` lifecycle/expiry around an `.extension` + `clientOnly` endpoint whose caller operations enforce grants through core sessions. |
| `S5` Visible `mutable-content: 1` push | Wave 1A (`runtime`), Wave 2 (`ffi`/`bindings`) | `validate_apns_loc_key` accepts only 1..=64 ASCII `[A-Za-z0-9_.-]` characters (defaulting to `"TENDRIL_WAKE_FALLBACK"`), forbidding dynamic text, format strings, args, or peer IDs in APNs alert payloads. |
| `S6` Direct HTTP/2 APNs and `HttpWakeProvider` | Wave 1A (`runtime`), Wave 2 (`ffi`/`bindings`) | `HttpWakeProvider::new()` loads `webpki_roots::TLS_SERVER_ROOTS` by default (`with_empty_roots()` only for explicit negative tests); endpoints retain one shared `Arc<dyn WakeProvider>` so `WakeCoalescer` and HTTP/2 pools persist; `ApnsH2WakeProvider` validates SSRF before connect, pins ALPN `h2`, validates `/3/device/<64..=200 hex>` on Apple hosts, supports mutually exclusive ES256 `.p8` JWT (cached 2700 s), bearer token, or mTLS auth, and zeroizes/redacts all key material. |

## Consequences

- **Non-extractable ML-DSA-65 custody without wire changes:** Wire v1/v2 formats, `HybridSigningPublicKey`, `HYBRID_MLDSA_CTX`, and Noise transcript rules remain unchanged; software and hardware-backed peers interoperate transparently. Because SEP hardware cannot execute Ed25519, Tier 2 protects the ML-DSA-65 key in SEP while the Ed25519 signing seed (`signing_seed_b64`, also backing relay control tickets) relies on Tier 1 SEP-wrapped `identity.sealed`, and full hybrid signatures still fail closed if either component fails verification.
- **Zero trust regression in bindings:** Swift owns only Keychain/SEP custody and Apple extension lifecycle APIs, while `tendril-core` enforces post-sign signature verification and custody monotonicity, and `tendril-runtime` owns APNs HTTP/2 transport, JWT signing, `loc-key` validation, and `WakeCoalescer` state.
- **Strict identity migration boundary:** Legacy `version: 1` identities continue loading unmodified in software mode and cannot silently bind an external signer, `version: 2` identities fail closed whenever an external ML-DSA-65 signer is missing or mismatches the persisted public key, and `External -> Software` rotations are rejected.
