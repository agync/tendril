# FFI ABI and cross-language bindings

Tendril keeps one Rust core (`tendril-core` + `tendril-runtime`) across every target language. Host-language bindings delegate wire framing, Noise handshakes, pairing codes, roster persistence, rotation verification, and default-deny capability checks directly to Rust rather than duplicating protocol logic.

## Core architecture

```
Host app (Go / Python / Node.js)
  -> Thin language wrapper (mutex / GIL release / N-API Promise)
    -> C ABI (`tendril-ffi`) or direct Rust bridge (PyO3 / napi-rs)
      -> `tendril-runtime` (`InboundRouter`, `StateStore`, `SessionDriver`) + `tendril-core`
```

- **Shared inbound routing (`InboundRouter`):** Peeks each incoming stream's cleartext preamble under the pre-auth rate limiter and dispatches `0x01` and `0x02` `Intent::Pair` and `Intent::Session` streams onto protocol-isolated bounded queues (`InboundQueue`s for v1/v2 pairing and sessions) with isolated half-open budgets, rate limiters, and automatic expiration (`DEFAULT_PRE_AUTH_TIMEOUT`), so unconsumed pairing floods never block or starve `accept_session` (and vice versa), while `set_pair_enabled(false)` disables and clears both v1 and v2 pair queues and `close()` wakes waiting callers immediately.
- **Durable roster persistence:** Host key rotations and rotation-fork revocations during `connect`, as well as CRL updates (including session-terminating `0x03 REVOCATION` frames), are persisted to `StateStore` across `tendril-ffi`, Python, and Node. These native `Endpoint` bindings assume single-process ownership of a `state_dir` (persisting atomic snapshots under `.roster.lock`), whereas multi-process CLI workflows (`tendril serve` paired with CLI subcommands) coordinate via transactional `StateStore::update_roster` updates and live `RosterStamp` reloads. `tendril-ffi` also exposes `tendril_endpoint_new_from_state` and `tendril_{endpoint_export_identity,endpoint_export_roster,session_export_roster}_json` for hosts that keep identity and roster in their own storage. The Kotlin and Swift bindings use `tendril_endpoint_new_sealed` instead: they keep only the identity sealed by the Keystore or Keychain (`identity.sealed`), and the runtime persists roster and group state in the same `state_dir` (see [Sealed local state](../design/groups.md#sealed-local-state)).
- **Full-duplex session concurrency:** `tendril-runtime` splits streams into `PathReader` and `PathWriter` (`PathStream::into_split`) behind `ConcurrentSession` (`reader -> writer -> machine -> roster -> pending_events` lock ordering, `shutdown()` wakeup, and fresh `current_unix_secs` reads inside `next_event_now`), so parked `poll_event` / `PollEvent` calls do not block `send_data`, `rekey`, `authorize`, or `close` / shutdown across FFI, Go, Python, and Node.
- **Go (`bindings/go`):** Links `libtendril_ffi` through cgo against `crates/tendril-ffi/include/tendril.h`, rejecting embedded NUL bytes in string parameters.
- **Python (`bindings/python`):** Builds a PyO3 `abi3-py39` extension module (`tendril._tendril`) with `unsafe_code = "forbid"`, releasing the GIL via `py.detach` around Argon2 derivation (`compute_code_mac`) and every `Endpoint`/`Session` (`Arc<ConcurrentSession>`) lock, disk I/O, or blocking runtime operation (`info_json` is a lock-free metadata serialization).
- **Node.js (`bindings/node`):** Builds a `napi-rs` 3 native addon on N-API v8 (`index.node`) with `unsafe_code = "deny"` (the `#[napi]` macros emit `allow(unsafe_code)` registration code, so `forbid` cannot be used), validating safe non-negative integers (`0..=Number.MAX_SAFE_INTEGER`) at the JS/N-API boundary and offloading Argon2 (`computeCodeMac`) and async `Endpoint`/`ConcurrentSession` operations onto Tokio so the JS event loop stays responsive.

### Pairing URIs and routes

The FFI marshals the runtime's multi-route pairing, Day-2 connect and route announcement code (`spec/pairing-v1.md`); it adds no pairing, roster or egress logic. Every call works on state-directory, sealed and store-less endpoints, and every `out_json` string is freed with `tendril_string_free`.

| Function | Contract |
|---|---|
| `tendril_endpoint_issue_pairing_uri(ep, options_json_opt, out_json)` | Options `{"kind": "auto"\|"lan"\|"remote", "host_name", "sign_routes"}` (`kind` in any case). Hints come only from the announced route set; add hints through `advertised_endpoints`. Returns `{"uri", "code_kind", "dropped", "uri_len", "qr_version_m", "route_seq"}`. `tendril_endpoint_issue_code` is unchanged. |
| `tendril_endpoint_pair_uri`, `tendril_endpoint_pair_v2_uri` `(ep, pairing_uri, name_opt, device_kind_opt, options_json_opt, out_json)` | Options `{"route_policy", "save_route", "endpoint", "code"}`. Wire v1 races the URI hints and commits once; Wire v2 tries rungs one at a time. An `endpoint` option is dialed alone and stored as an `operator` route. A `code` option replaces the URI code; an empty one fails `-1` (`pairing code invalid`) before any dial. Returns `{"device_id", "host_id", "sas", "status", "host_confirmed", "provider", "endpoint", "committed", "route_check", "routes_persisted", "routes_reason", "skipped"}`. A failure message names the skipped hints, each failed candidate and whether the code may be spent. |
| `tendril_session_connect`, `tendril_session_connect_v2` | A `NULL` or `""` `endpoint` dials the peer's stored routes; a non-empty one is an explicit operator endpoint, normalized and dialed alone. Both send `route_seq` and ingest route sets under the endpoint's route policy. A Wire v2 connect (`tendril_session_connect_v2`, or `tendril_session_connect_with_options` with `"wire": 2`) to an explicit endpoint on an endpoint with a configured `WakeProvider` runs the wake: the hint goes out before the first attempt with `wake_pre_wake`, otherwise after a failed one, and the same policy connect then runs up to `wake_max_attempts` times, so a woken session also negotiates and ingests routes and honours a recovery URI. Only an uncommitted miss a wake can fix (I/O, timeout, closed, or a relay reporting the host's mailbox `offline`, on every candidate) sends the wake hint or is retried; a committed attempt, a key, pin or grant failure, a relay admission refusal and a protocol failure such as no dialable stored routes are final. |
| `tendril_session_connect_with_options(ep, target_host_id, options_json)` | Options `{"wire": 1\|2, "grant", "endpoint", "relay_host", "recovery_uri", "replace_routes", "route_policy"}`. `relay_host` is the expected relay host of an explicit `endpoint` (the Iroh relay mode for `iroh://`), as in `tendril_session_connect`. A `recovery_uri` (with or without `endpoint`) has its keys checked before session `msg3`; a signed one adds its hints and replaces the `signed` routes when its `rq` is newer, or with `replace_routes`. Its code is never sent. |
| `tendril_endpoint_set_peer_routes(ep, peer_id, routes_json)` | Replaces the `operator` routes with a JSON array of endpoint strings (at most six); one bad entry rejects the list and nothing is written. Returns `0`, `TENDRIL_ERR_INVALID_ARG` for a bad list or `TENDRIL_ERR_NOT_FOUND` for an unknown peer or `TENDRIL_ERR_PROTOCOL` for a pending or revoked one. |
| `tendril_endpoint_peer_routes(ep, peer_id, out_json)` | `{"routes": [{"hint", "source"}], "route_meta": {"seq", "issued_at", "origin"} \| null, "last_route_set": {"outcome", "seq"} \| null}`. |
| `tendril_endpoint_clear_peer_routes(ep, peer_id, source_opt)` | `NULL` or `"operator"`, `"signed"`, `"committed"`, or `"all"`. `route_meta` is kept. |
| `tendril_endpoint_apply_route_uri(ep, pairing_uri, options_json_opt, out_json)` | Offline application of a fresh signed URI to the paired host whose `k` and `sh` it carries. Options `{"replace_routes", "route_policy"}`. Returns `{"peer_id", "applied", "reason", "route_seq"}`. |
| `tendril_endpoint_refresh_routes(ep, snapshot_json_opt, out_json)` | Host re-scan. `snapshot_json_opt` is `NULL` or the complete network snapshot `{"networks": [{"id", "iface", "if_index", "transports", "addrs"}]}`; a snapshot is retained and `NULL` re-enumerates natively (Android reuses the retained snapshot). `out_json` may be `NULL`, otherwise `{"route_seq", "changed"}`. |

**Configuration.** `tendril_endpoint_configure_transports_json` also accepts `advertised_endpoints` (array of hints), `relay_auth_origins` (array of `scheme://host[:port]`, each validated; relay admission material goes only to these origins or to the explicit endpoint of a call), `advertise` (`"auto"`, the default, or `"explicit"`), `route_policy` (`"all_signed"`, the default, `"committed_only"` or `"none"`) and `sign_routes` (default `true`). The crate feature `auto-advertise` (on by default) enables native interface enumeration for `advertise: auto`.

**Hosting.** Each endpoint owns a route announcer. The first `serve_*` call, pairing URI issuance or `tendril_endpoint_refresh_routes` makes the endpoint a host: from then on a served listener or a transport configuration change republishes the announced set, and a 60 s timer re-enumerates and sends scheduled route sets. `tendril_endpoint_close` ends hosting for good: afterwards `tendril_endpoint_issue_pairing_uri` and `tendril_endpoint_refresh_routes` return `TENDRIL_ERR_CLOSED` ("endpoint is closed"), a `serve_*` call still returns `0` but starts no timer and publishes nothing, and a closed endpoint is never reopened. `tendril_session_accept` and `tendril_session_accept_v2` register each session before returning it, so a newer signed set is its first host-initiated frame; when registration fails the accept returns `NULL` with the last error set and closes the session (close code `1011`). Route sets never reach `tendril_session_poll_event`. Locks follow the runtime order (async store lock, roster file lock, pairing manager, in-memory roster): issuance publishes before it takes the pairing manager, so issuing pairing URIs while `tendril_endpoint_pair_accept` or `tendril_endpoint_pair_v2_accept` claims a code never deadlocks, and no FFI call holds the pairing manager or the in-memory roster across announcer or roster store I/O.

**Legacy pairing.** `tendril_endpoint_pair_initiate` and `tendril_endpoint_pair_v2_initiate` store no route, not even the endpoint they dialed. After such a pairing, `tendril_session_connect(ep, NULL, ...)` has nothing to dial until the app sets a route with `tendril_endpoint_set_peer_routes`, connects with an explicit endpoint, or pairs from a pairing URI.

**Revocation state.** Route writes (route set ingest, the route setter and clear calls, offline application), every other FFI roster write (including a CRL a Wire v1 session persists) and every roster reload keep CRLs that a live session accepted but has not yet persisted: the in-memory CRLs are merged into the roster before it is written or replaced, so a route write never drops revocation evidence.

**Error text.** `tendril_last_error` never echoes raw caller input. Every message passes the shared runtime redactor (`tendril_runtime::redact`): a URL-shaped value keeps only `scheme://host[:port]` (no user info, path, query or fragment), a hint in a failure list is redacted on its own, a pairing code in any case and a token with `@` or a query become `<redacted>`, and a quote starts a value that is redacted to the end of its line. A JSON error (options, transport configuration, string lists such as `routes_json`, a network snapshot) reports only its category, line and column; an invalid code kind or relay ticket role is never echoed; an invalid `relay_auth_origins` entry is named by its index. The same rules apply on every surface; see [Diagnostics and redaction](#diagnostics-and-redaction).

Notes on the table:

- **Results.** C, Swift and Kotlin return the C ABI's JSON strings as-is; Python and Node return them as-is for most calls (Node as a `Promise`); Go decodes them into typed structs. Every pairing result carries `routes_reason` (null, or `unsigned_uri`, `route_key_rotated` or `stale_route_seq` when no routes were written), and Python and Node add `wire_version` on v2.
- **Route policy spelling.** `all_signed`, `committed_only`, `none` in JSON and Go; `allSigned`, `committedOnly`, `none` in the browser; `RoutePolicy.ALL_SIGNED` and the other enum values in Kotlin.
- **Blocking and async.** Node methods that do network or long store work return Promises; the inventory marks the synchronous exceptions. Python releases the GIL during them. Kotlin and Swift calls block the calling thread, so run them off the main thread.
- **Hosts.** A browser has no listener, so it does not issue URIs, advertise, or refresh routes. It applies announcements from hosts it has paired with.
- **Route configuration merges.** `tendril_endpoint_configure_transports_json` replaces the whole transport configuration on each call. Go `ConfigureRoutes`, Swift `configureRoutes` (and `configureP2p`) and Kotlin `configureRoutes` therefore keep the last full configuration the binding sent (including the whole-configuration call of each binding) and merge only the route keys you pass into it, so relay credentials, P2P and wake settings are never reset. The cache updates only after the native call succeeds, a failed merge leaves it unchanged, and Go, Swift and Kotlin clear it when the endpoint closes because their runtimes cannot zeroize the secrets it holds. A key you leave unset (`nil`, `null`, zero) keeps its value. In Go, `RouteConfig.AdvertisedEndpoints` and `RelayAuthOrigins` are `*[]string`: `nil` keeps the current list and a pointer to an empty slice clears it.
- **Rust.** The Rust runtime exposes the same operations through `PairPolicyOptions`, `SessionDriver::connect_with_policy_and_store`, `ConnectOpts`, `apply_signed_route_uri` and `RouteAnnouncer`.

### Diagnostics and redaction

No surface echoes raw URLs, hints, relay URLs, pairing URIs, pairing codes or caller input in an error, a log line or an exception. One set of helpers does it, in `tendril-core` (`redact`) and re-exported as `tendril_runtime::redact`; the CLI, the C ABI and the Python and Node bindings call it, and the browser relies on the same core errors.

| Helper | Output |
|---|---|
| `redact_url`, `redact_url_str` | `scheme://host[:port]` only. Anything unparseable, a URL with a backslash, a host outside plain DNS, IPv4 and IPv6 characters, or an `@` in the path, query or fragment becomes `<redacted>`. |
| `redact_hint` | One endpoint hint. A URL hint keeps `scheme://host[:port]`. A hint without `://` keeps `provider:host:port` only for the providers `direct`, `local`, `overlay`, `relay`, `broker` and `p2p` with a plain host and port, `provider:<redacted>` when the rest is not, and `<redacted>` for any other prefix. |
| `redact_host` | A bare host or IP literal under the same host rules. |
| `redact_text` | Free-text scrubber for messages built elsewhere. A URL ends only at whitespace or a closing quote and keeps a known scheme and its authority; text glued in front of it is redacted. A token with `@`, a backslash, a `%` escape, an IPv6 zone id or a query is redacted. A quote starts a value that is redacted to the end of its line. |
| `redact_json_error` | `invalid JSON (<category>) at line L column C`, never the offending input. |
| `redact_error` | `redact_text` of a runtime error's display text. |

Pairing codes never pass any helper: `TND-` in any case, or two or more four-character groups in a hyphen-joined run, with or without a prefix. Redaction runs on the pieces (each hint, origin or URL) before they are formatted into a message, and once more over the final text, which leaves already redacted text unchanged.

Core errors never contain the input in the first place. A pairing URI that does not parse reports only the failure (`unknown query parameter`, `duplicate query parameter`, `invalid hint`), never the parameter name or value. Egress and relay errors print `redact_host` or `redact_hint` output, and WebSocket connect, URL and scheme errors from the relay and broker dialers pass through `redact_text`.

| Surface | Where it applies |
|---|---|
| CLI | Error text, the `attempt_failed` line (`skipped`, `failures`), `dropped_endpoints`, and invalid `--relay-auth-origin` values. See [Diagnostics and redaction](../usage/cli-demo.md#diagnostics-and-redaction). |
| C ABI, Go, Swift, Kotlin | `tendril_last_error`. A JSON error reports its category, line and column. |
| Python | Every `RuntimeError` and `ValueError` message. A JSON option error is `invalid <option>: invalid JSON (<category>) at line L column C`. |
| Node | Every thrown `Error` message (status `GenericFailure` or `InvalidArg`), with the same JSON error form. |
| Browser | Core errors that reach JavaScript never echo input. Hints in a connect error list go through `redactHint` (`scheme://host[:port]` or `<redacted>`). A `skipped` entry on a result keeps the hint, for display by the app that already holds the URI. |

A failed pairing or connect from Python and Node reads `<error>; committed: the pairing code may be spent; skipped: <hint> (<reason>), ...; candidates: <hint> [<provider>]: <error>; ...`, each hint redacted on its own.

### Lock order for SDK embedders

Code that drives `tendril-runtime` directly (a Rust host, or a binding of your own) takes four locks, always in this order and never the reverse:

1. the endpoint's async store lock, if the surface has one;
2. the roster file lock (`.roster.lock`, an advisory `flock` taken by `StateStore` transactions);
3. the pairing manager mutex;
4. an in-memory roster mutex (`RosterAccess`'s roster, or a responder's).

A pairing claim holds the roster file lock while it burns a code under the pairing manager (locks 2, then 3). `RouteAnnouncer::issue_pairing_uri` publishes first, which loads and updates the store under the roster file lock, so it must not run with the manager already held, or it deadlocks against a claim that holds the file lock and waits for the manager. It therefore takes `&Mutex<PairingManager>`, publishes, and locks the manager only for the in-memory issuance. Rules for embedders:

- Do not hold the pairing manager, or an in-memory roster mutex, across any `RouteAnnouncer` or `RosterAccess` call.
- Take the in-memory roster mutex only after the roster file lock, for short in-memory work, never while waiting for the file lock and never across an `.await`. `RosterAccess::update` runs your callback on the committed roster with the mutex released, then publishes the result under it.
- A client session's route ingest slot sits before the file lock: its blocking task holds the slot while it takes the file lock and then the in-memory roster. A session never takes the slot while it holds its own machine or roster mutex.

Issuing pairing URIs while a store-backed host claims a code (`tendril_endpoint_pair_accept`, `pair_v2_accept`, and their Python and Node equivalents) is covered by a concurrency test in the runtime. Every surface (CLI, C ABI, Python, Node) uses the same API.

### Typed failures

Wake retries, ranking and surface messages key on typed errors, never on message text.

| Error | Meaning |
|---|---|
| `RuntimeError::RelayOffline(kind)` | A relay answered `offline`: the dialed host holds no registration there. Kinds: `V1Dial`, `V2Dial`, and `PinnedKey` (every relay candidate of a Day-2 connect was offline for the pinned key, with no recovery URI; the text suggests another route or a fresh pairing URI). `is_relay_offline()` tests for it. |
| `RuntimeError::Egress { reason, detail }` | A hint or WebSocket lookup the egress policy refused (`blocked_address`, `unresolved`, `invalid`, ...). `skip_reason()` returns the reason. |
| `RuntimeError::Timeout("argon2id permit wait timed out")` | A Wire v2 initiator waited for a process-wide Argon2id permit longer than its budget. Nothing was sent and the attempt is uncommitted. See [Wire v2 privacy](../design/wire-v2-privacy.md). |
| `AttemptError::is_transient_precommit()` | Uncommitted, and the error and every candidate failure is `Io`, `Timeout` or `Closed`. |
| `AttemptError::is_wakeable_miss()` | `is_transient_precommit()`, or uncommitted with every failure `Io`, `Timeout`, `Closed` or `RelayOffline`. The only predicate that sends a wake hint or retries on the CLI, C ABI, Python and Node (the `tendril-conformance-peer` test tool still pre-dials and retries on any dial error); see [Wake around a connect](../design/wake-providers.md#wake-around-a-connect). |

A Day-2 connect that established a session and then failed the final authorization check (or its roster transaction) reports `committed: true` on both wires. The browser ranks candidate errors by their stable `code`; see [Web and mobile bindings](web-and-mobile.md).

### `TendrilResult` status codes

- `TENDRIL_OK` (`0`): operation succeeded.
- `TENDRIL_WOULD_BLOCK` (`1`): timed poll completed with no queued event ready.
- `TENDRIL_EOF` (`2`): peer stream ended cleanly.
- Negative codes (`TENDRIL_ERR_INVALID_ARG` `-1`, `TENDRIL_ERR_NOT_FOUND` `-2`, `TENDRIL_ERR_CLOSED` `-5`, `TENDRIL_ERR_PROTOCOL` `-6`, `TENDRIL_ERR_INTERNAL` `-7`): error details are readable via `tendril_last_error`.

## Group mesh C ABI

Small peer mesh groups ([design](../design/groups.md), `spec/groups-v1.md`) reach host languages as thin calls over `tendril-runtime` (`GroupPool`, `GroupHub`, and the admin facade). Bindings never build manifests, evaluate authorization, or see the rendezvous key or pairwise secrets. Admin calls return public manifest JSON only, and every group API needs an endpoint with a state directory (`"groups require a state directory endpoint"`, `TENDRIL_ERR_INVALID_ARG`).

| Function | Purpose |
|---|---|
| `tendril_group_create(ep, name, min_wire_version, endpoints_json, out_manifest_json)` | Root creates a group and persists manifest and secrets |
| `tendril_group_add_member(ep, group_id, peer_id, caps_json, endpoints_json, out_manifest_json)` | Add a roster peer with a known signing key (M2M-enrolled, or code-paired; peers code-paired before the signing key claim must re-pair and confirm first). Every roster entry whose stored or static-derived device id is `peer_id` counts: any revoked entry refuses the add, otherwise one `Active` entry with a signing key is used; `caps_json` and `endpoints_json` are null or a JSON array of strings |
| `tendril_group_remove_member(ep, group_id, peer_id, out_manifest_json)` | Revoke the member and rotate the rendezvous key |
| `tendril_group_ingest_manifest(ep, manifest_json, sender_peer_id, out_group_id)` | Ingest a manifest from an authenticated peer; `sender_peer_id` must be the peer that delivered it, and first-contact pinning (F11) applies |
| `tendril_group_open(ep, group_id, listen_addr, out_group)` | Open a `TendrilGroup *`; `listen_addr` may be NULL, otherwise a direct listener is bound and served |
| `tendril_group_local_endpoint(group, out_endpoint)` | Endpoint bound by `listen_addr`, or `*out_endpoint == NULL` when none |
| `tendril_group_sync(group, out_report_json)` | Admin push of manifest and rendezvous key to members; needed for Wire v2 groups |
| `tendril_group_broadcast(group, required_cap, data_ptr, data_len, out_report_json)` | Fan out to members; NULL `required_cap` means `group.send:<group_id>`; report is `{delivered, offline, failed}` with `failed` as `[device_id, error]` pairs |
| `tendril_group_poll_event(group, timeout_ms, out_event_json)` | `TENDRIL_OK` with an event, `TENDRIL_WOULD_BLOCK` on timeout, `TENDRIL_EOF` once the pool is closed; a parked poll returns `TENDRIL_EOF` promptly when the handle closes |
| `tendril_group_authorize_peer(group, peer_id, cap)` | `TENDRIL_OK` when the peer holds `cap`; any refusal sets the last error |
| `tendril_group_close(group)`, `tendril_group_free(group)` | Idempotent close, then free |

**Ownership.** Free every `char **` out string with `tendril_string_free`. `tendril_group_close` is idempotent, releases the handle's `listen_addr` listener so the port is reusable, and later calls on the handle (including `tendril_group_poll_event`) return `TENDRIL_ERR_CLOSED`; `tendril_endpoint_close` shuts down the group hub; `tendril_group_free` is safe after close and must not race with other calls on the handle. The FFI adds a p2p dialer (feature `p2p-iroh`) only when a p2p relay mode is configured explicitly or `TENDRIL_P2P_LOCAL=1` is set. The first `tendril_group_open` on an endpoint routes its inbound session streams through the group hub, so configure transports before it. Ordinary sessions still arrive through `tendril_session_accept` and `tendril_session_accept_v2`. A call already parked in either accept function when the first group opens switches to the group channels at once, and the hub registers every stored group before it handles a stream. Once groups run, `tendril_session_accept` and `tendril_session_accept_v2` apply `timeout_ms` to the whole wait for a group-routed session, including waiting behind another concurrent accept; a call that was parked on the router when the first group opened and dequeues a stream at that moment completes that stream's handshake under the pre-auth timeouts, outside `timeout_ms`.

**Python and Node.** `group_open` and `groupOpen` build a standalone `GroupPool` per call and run no hub, so inbound sibling sessions are accepted only on that group's own `listen_addr`; pass one on every member that must be dialed. With `relay_listen=True` (Python) or `relayListen: true` (Node) the pool also registers its relay mailboxes on the relay hints of its own manifest entry and accepts siblings there; pass it on the one process that serves the identity, since a relay keeps only the latest registration. The pool never registers on the relay host of a URL served with `serve_relay` (`serveRelay`) on the same endpoint (matched by host, not by exact URL or port), so the endpoint keeps that mailbox and siblings reach the group through its other endpoints. Each open reads that list once, so let every `serve_relay` call return before `group_open`: a pool opened earlier competes with a later `serve_relay` on a relay host named in the member's own entry. Relay dials and registrations use the endpoint's relay auth (`relay_auth_secret` or `relay_ticket` through `configure_transports_json` or `configureTransportsJson`). Admin onboarding also works through ordinary sessions the host accepts and polls. A p2p dialer for `iroh://` member endpoints is added only when a p2p relay mode is configured explicitly or `TENDRIL_P2P_LOCAL=1` is set, as in the FFI; other `p2p_*` settings alone never add one. `Endpoint.close` closes every group still open on the endpoint, and later calls on those groups fail with `group is closed`.

**Relay limits.** A `/v2/relay` manifest endpoint is dialed on the target's group mailbox while the current key is held; any other relay endpoint is dialed with the target's manifest `relay_pub`. The FFI group hub passes the endpoint's relay auth and registers each group's mailbox on the `/v2/relay` hints of the local member's own entry (and the identity's mailbox on its other relay hints), as `tendril serve` does, from the first `tendril_group_open`; configure transports (relay auth) first, and let every successful `tendril_endpoint_serve_relay` call return before the first `tendril_group_open`, since the hub reads the URLs served that way once, when it starts (calls that overlap the first open are not covered, and an open that starts the hub but returns no group handle still starts it), and leaves the relay hosts of those URLs (matched by host, not by exact URL or port) to the app. Hub discovery of stored groups runs only when the hub starts and on each `tendril_group_open`, and nothing retries it: a group stored later opens on the next `tendril_group_open`, and a group whose pool failed to open (for example because its root CRL could not be resolved) stays unreachable, even after the roster is repaired, until another `tendril_group_open` on that endpoint. Only a pool that did open reconciles its relay registrations on its own 250 ms tick. An admin push to a member that holds no current key reaches it over a `/v2/relay` endpoint only through its ordinary pair mailbox listener: `tendril_endpoint_serve_relay_v2`, `serve_relay_v2`, `serveRelayV2`, or `tendril serve --relay`, with the host accepting and polling the session. See [Small peer mesh groups](../design/groups.md#known-limitations).

**Error mapping.** `GroupNotFound` and unknown peers return `TENDRIL_ERR_NOT_FOUND`, a closed pool or handle returns `TENDRIL_ERR_CLOSED`, I/O and storage failures return `TENDRIL_ERR_INTERNAL`, malformed arguments (including a store-less endpoint) return `TENDRIL_ERR_INVALID_ARG`, and every other core refusal (for example `GroupUnauthorized`, `GroupSeqRollback`, `GroupManifestFork`) returns `TENDRIL_ERR_PROTOCOL`. The core error name and message are preserved in `tendril_last_error`.

**Group event JSON** (`tendril_group_poll_event`):

- **Transport keys.** `configure_transports_json` accepts `relay_auth_secret`, `relay_ticket`, `p2p_relay_mode`, `p2p_relay_urls`, `p2p_pkarr`, `p2p_advertise_direct_addrs`, `p2p_allow_private_addrs`, `p2p_port_mapping` (boolean, default `true`; `false` stops the endpoint from probing the router for a UPnP, NAT-PMP or PCP mapping), `p2p_bind_addrs` (at most one IPv4 and one IPv6 socket address such as `"0.0.0.0:0"` and `"[::]:0"`, default every interface; an invalid entry is an error naming `p2p_bind_addrs`), `p2p_relay_auth_token`, `p2p_api_secret`, `wake_url`, `wake_adapter` (`webhook`, `unified_push`, `apns`, `apns_h2`, `fcm`), `wake_secret_b64`, `wake_auth_token`, `wake_pre_wake`, `wake_retry_delay_ms`, `wake_max_attempts`, `wake_timeout_ms`, `wake_coalesce_secs`, `wake_apns_mode`, `wake_apns_topic`, `wake_apns_loc_key`, `wake_apns_team_id`, `wake_apns_key_id`, `wake_apns_p8_pem`, `wake_apns_client_cert_pem`, `wake_apns_client_key_pem`, `relay_auth_origins`, `advertise`, `advertised_endpoints`, `route_policy` and `sign_routes`. Node accepts every key in snake_case and in camelCase (`relayAuthSecret`, `p2pPkarr`, `p2pPortMapping`, `p2pBindAddrs`, `wakePreWake`, `wakeCoalesceSecs`, `wakeApnsMode`, `wakeApnsTopic`, `wakeApnsLocKey`, `wakeApnsTeamId`, `wakeApnsKeyId`, `wakeApnsP8Pem`, `wakeApnsClientCertPem`, `wakeApnsClientKeyPem`, `relayAuthOrigins`, `advertisedEndpoints`, `routePolicy`, `signRoutes`, and so on). An unknown key is an error in both. `p2p_relay_mode` accepts `n0` as an alias of `default`. The sockets these keys control are listed under [Sockets a P2P endpoint opens](../design/providers-and-relay-ladder.md#sockets-a-p2p-endpoint-opens). Swift sets `p2p_port_mapping` and `p2p_bind_addrs` with `configureP2p(portMapping:bindAddrs:)`, which merges them into the last configuration like `configureRoutes`. Kotlin does not expose them yet.
- **Enrolment routes.** `tendril_endpoint_enroll_initiate`, `enroll_initiate` and `enrollInitiate` enrol through the routes driver under the endpoint's `route_policy` (default `all_signed`) with the endpoint they dialed as the operator endpoint, so a restart connects from the stored routes alone. The result JSON adds `routes_persisted` (`[]` under `none`), `route_warnings` and `routes_reason`. An endpoint without a state directory has no store for routes: it requests and stores none whatever its policy, pins the host in memory, and reports `routes_reason: "no_state_dir"`. The CLI is `tendril enroll --route-policy <all-signed|committed-only|none>`; its result carries `routes_reason: null`, as every CLI endpoint has a state directory. The default `all_signed` asks the host for its route set, and a host that predates route sets rejects that claim as a protocol error before it spends the token: enrol with `route_policy` `"committed_only"` (still saves the endpoint dialed) or `"none"` in the transport configuration (`--route-policy committed-only` or `none` on the CLI) until the host is upgraded.
- **Wake.** A configured wake target applies to Wire v2 connects with an explicit endpoint, in `pre_wake` or after-a-wakeable-miss order, as in [Wake around a connect](../design/wake-providers.md#wake-around-a-connect). Both bindings use the same retry predicate as the CLI and the C ABI.
- **Empty code.** A `code` option of `""` in the options of `pair_uri` and `pair_v2_uri` (`pairUri`, `pairV2Uri`) is rejected before any dial as `pairing code invalid`; it never falls back to the URI's own code.
- **Route set verification.** `verify_route_set(payload: bytes, signing_pub: bytes) -> str` (`verifyRouteSet(payload: Buffer, signingPub: Buffer): string`) strictly decodes a `0x0C ROUTE_SET` payload with `RouteSet::decode` and checks its hybrid signature against the 1984-byte `signing_pub` with `RouteSet::verify`. It returns JSON `{"seq", "issued_at", "routes"}` only when both succeed. Failures raise `ValueError` (throw `Error`) with the message `signing key invalid`, `route set decode failed` or `route set signature invalid`. There is deliberately no unverified decode, and binding the key and sequence to a pinned peer stays with the roster. Typings live in `bindings/python/tendril/__init__.pyi` and `bindings/node/index.d.ts`; the conformance vectors in `spec/vectors/routes.json` drive it from `bindings/python/tests/test_routes_vectors.py` and `bindings/node/test/routes_vectors.test.mjs`.
- **Errors.** Python raises `RuntimeError` for runtime failures and `ValueError` for bad arguments; Node throws `Error` with status `GenericFailure` or `InvalidArg`. Messages are redacted (see [Diagnostics and redaction](#diagnostics-and-redaction)).
- **Typings.** Node's `bindings/node/index.d.ts` declares every method above. Python exposes `Endpoint`, `Group`, `Session` and the module functions from `tendril`.

Full M2M enrollment parity (`addTrustAnchor`, `revokeTrustAnchor`, `mintEnrollmentToken`, and `enroll` / `enrollInitiate`) also extends across browser WebAssembly, Android Kotlin JNI, and Apple Swift; see [Web and mobile bindings](web-and-mobile.md).

## Verification

Each binding verifies the helper-level `spec/vectors/` files (`fingerprints.json`, `pairing_mac.json`, `rotation.json`, and `grants.json`) offline (while `spec/vectors/handshake.json` and `spec/vectors/m2m_enrollment.json` are verified in Rust and Go via `make vectors/check`) and runs bidirectional client/host live interop against `tendril-conformance-peer` (covering pairing, SAS confirmation, M2M enrollment/replay/anchor-revocation, capability minting, encrypted data exchange, authorization, revocation, plus `rekey` in Python/Node bidirectional runs and Go concurrency tests):

The Python, Node, Web and Swift suites also replay `spec/vectors/routes.json`: the `route_set` vectors through `verify_route_set` / `verifyRouteSet` (Web through the WASM roster; Swift skips this section because the C ABI has no route set verifier), and the `pairing_route_statement` and `pairing_route_check` vectors through the offline route URI apply. For the check cases they assert the `route_check` outcome only; relay pin, commit error, operator key and rotation fields belong to the pairing handshake, which the Rust and Go suites replay. Each suite lists the sections and fields it skips, so a new one fails until someone decides.

```bash
make bindings/go      # build tendril-ffi and run Go cgo tests with -race
make bindings/python  # build _tendril.so and run Python unittest suite
make bindings/node    # build index.node and run node --test suite
make bindings/check   # run Go, Python, Node, Web WASM, and Kotlin JNI suites
make check            # run full workspace lint, Rust tests, vectors, and bindings
```
