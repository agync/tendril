# Web and mobile bindings

Browser and mobile targets run the same Rust protocol core as desktop targets. Browsers execute a sans-I/O WebAssembly build over `WebSocket`, while Android and Apple targets call `crates/tendril-ffi` (`tendril.h`) with platform keychain and network-transition integration.

## Architecture across targets

| Target | Bridge Crate / Layer | Transport Path | Secure Storage & Platform Integration |
|---|---|---|---|
| Browser (`bindings/web`) | `crates/tendril-wasm` (`#![forbid(unsafe_code)]`, `wasm-bindgen = "=0.2.130"`, opt-in `p2p-iroh` feature) | Browser `WebSocket` (`/v1/relay`, `/v2/relay`, `broker+ws(s)://`) and opt-in `iroh` over `ws_stream_wasm` (`n0_dns` lookup only for explicit operator dials; hint dials use the configured or Default relay map) | `TendrilWebClient`, `dialBrokerStream`, `dialIrohStream`, `computeCodeMacWorker` Web Worker Argon2 offload |
| Android (`bindings/kotlin`) | JNI C shim (`bindings/kotlin/jni/tendril_jni.c`) -> `libtendril_ffi.so` | Rust `P2pListener` / `RelayDialer` / `DirectDialer` (`serveP2p` via `p2p-iroh`) | `KeystoreStateCipher` (`AndroidKeyStore` AES-256-GCM), `TendrilForegroundService` (`NetworkCallback`) |
| Apple (`bindings/swift`) | SwiftPM C target (`CTendril`) -> `libtendril_ffi` | Rust `P2pListener` / `RelayDialer` / `DirectDialer` (`serveP2p` via `p2p-iroh`) | `TendrilKeychainStore` (`Security` Keychain + `CryptoKit` AES-GCM) |

## WebAssembly core and browser SDK

### `crates/tendril-wasm`

`crates/tendril-wasm` compiles cleanly for `wasm32-unknown-unknown` using `.cargo/config.toml` (`getrandom_backend="wasm_js"`). Its default build (`bindings/web/pkg`) remains strictly sans-I/O and exports four stateful types plus nine helper functions; enabling the opt-in `p2p-iroh` feature (`bindings/web/pkg-p2p`) adds `WasmIrohStream` and `parse_p2p_endpoint_json` over `iroh` 1.5 (`ws_stream_wasm` + `ring`):

- `WasmIdentity`: generates, exports, and restores client hybrid Ed25519 + ML-DSA-65 signing keys (`signing_pub`, `signing_pub_hash`, `relay_pub`) and X25519 static keys without touching host storage directly, mints single-use M2M enrollment tokens via `mint_enrollment_token`, and mints Tier 3 relay tickets via `mint_relay_ticket_json`.
- `WasmRoster`: serializes and atomically replaces (`replace_from_json`) pinned hosts, pairing state, verified CRL sequence tracking, M2M trust anchors (`add_trust_anchor`, `revoke_trust_anchor`), and v2 peer metadata (`pairing_floor`, `peer_v2_summary`, `derive_v2_relay_dial_for_peer_json`).
- `WasmPairInitiator` and `WasmV2PakePairInitiator`: sans-I/O `Intent::Pair` handshake state machines (`start`, `feed_bytes`). `WasmPairInitiator` drives v1 pairing and M2M enrollment (`WasmPairInitiator.new_m2m`), with `new_with_roster` and `new_m2m_with_roster` enforcing persisted `min_wire_version` upgrade floors; `WasmV2PakePairInitiator` drives Wire `0x02` PAKE pairing.
- `WasmSessionClient` and `WasmV2SessionInitiator`: sans-I/O `Intent::Session` initiators (v1 `WasmSessionClient`: `send_data`, `send_ping`, `send_rekey`, `send_close`, `tick`, `authorize`; v2 `WasmV2SessionInitiator`: `send_data`, `rekey`, `close`, `tick`, `authorize`, `send_dummy_cover`, `next_ping_delay_ms`, `send_ping` for Wire `0x02` pseudonymous reconnect with padded/jittered frames).
- Vector and verification helpers: `device_id`, `fingerprint_host`, `fingerprint_device`, `pairing_sas`, `compute_code_mac`, `compute_code_mac_bytes` (zeroizing the caller byte slice after hashing), `verify_rotation_chain_json`, `verify_grant_json`, `parse_pairing_uri_json`, `compute_relay_auth_hmac_b64`, `canonical_relay_host` (normalizing IPv6, trailing-dot, and mixed-case hosts while preserving raw v1 HMAC hosts), `derive_v2_relay_dial_json`, and `v2_epoch_within_skew`.
- `WasmGroupBook` (`crates/tendril-wasm/src/group.rs`): the browser group book. It ingests manifests and `group_manifest_unverified` session events (`ingest_manifest`, `ingest_manifest_event`), authorizes peers (`authorize_peer`), lists members, and computes broadcast targets, all by calling `tendril_core::group`. Root-side create, add, and remove are not exposed. `WasmSessionClient` and `WasmV2SessionInitiator` expose `apply_group_rendezvous` so a `0x0B` frame received on an authenticated session is applied to the book. The book export (`to_json_bytes`) contains rendezvous keys, so it is vault-bound like the roster export.
- Pairing URIs and routes (`spec/pairing-v1.md` Section 6): `parse_pairing_uri_json` also returns `providers`, `relay_pub_b64`, `route_seq` and `route_signed`. `WasmPairInitiator` and `WasmV2PakePairInitiator` defer the claim: `feed_bytes` reports `host_verified` with `relay_pub_ok` and `route_check` (`verified`, `unsigned`, `route_key_rotated` or `invalid`), and `commit_claim()` returns `msg3` only after the page checks them. Session initiators accept `with_route_expectation` and `with_route_seq` before `start()` and expose `presented_rotation_json`, `verified_recovery_statement_json` and `take_route_sets`. `WasmRoster` adds `pin_snapshot`, `clone_roster`, `session_candidates` (admitting `broker+ws(s)://` and `allow_insecure_ws`, sorted by `tendril_core::policy::sort_key` so `/v2/relay` precedes `/v1/relay` and numeric hosts precede DNS hosts), `check_established_session`, `reconcile_rotation_evidence`, `apply_verified_rotation_json`, `merge_crl_evidence`, `export_crls_json`, `apply_route_announcement`, `set_routes` and `apply_signed_route_uri`. `WasmPathPlanner` wraps `tendril_core::policy::PathPlanner` (`start`, `tick`, `on_dial_succeeded`, `on_dial_failed`, `drain_actions`, `next_deadline_ms`) with `250 ms` stagger, `500 ms` P2P cold-start hold, per-attempt timeout, and exhaustion timeout tracking. `classifyPairingCode` and `relayAuthOriginAllowed` are exported helpers. Every export calls the shared core function.
- Opt-in browser P2P (`p2p-iroh` feature): `WasmIrohStream` (`dial`, `dial_with_options`, `send_chunk`, `recv_chunk`, `close`) and `parse_p2p_endpoint_json`.

### `@tendril-sdk/web` (`bindings/web`)

- `bindings/web/src/relay.js` implements `spec/relay-v1.md` (`/v1/relay`), `spec/relay-v2.md` (`/v2/relay` via `dialRelayV2Stream`, requiring `deriveV2Dial` for epoch-blinded `dial_token` proofs), and raw binary WebSocket broker streams (`dialBrokerStream` and `validateBrokerWsUrl` for `broker+wss://` and loopback or `allowInsecureWs` `broker+ws://`), client WebSocket handshakes (`challenge`, `dial`, `ready`, optional 0-RTT `initFrame` / `Dial.init_frame` gated on `challenge.fast_open === true` and surfaced via `RelayStream.fastOpenSent`, plus Tier 2 HMAC `computeRelayAuthHmacB64` and Tier 3 `RelayTicket` admission proofs), canonical relay host normalization (`canonicalRelayHost` / `canonical_relay_host`), URL validation (`validateRelayWsUrl`: rejecting control characters, userinfo, fragments, metadata/link-local/unspecified hosts, and cleartext `ws://` off-loopback unless `allowInsecureWs: true` is passed), `AbortSignal` (`signal`) cancellation across all WebSocket and P2P dialers without leaking timers or unhandled rejections, binary frame bounds (`65,521` bytes max), and bounded receive queueing (`MAX_QUEUED_BYTES = 16 * 65521`, `MAX_QUEUED_FRAMES = 256`, late post-close frame drops, and queue cleanup on `close()`).
- `bindings/web/src/index.js` dynamically imports `./iroh.js` (`bindings/web/pkg-p2p/` on demand for `iroh://`, isolating `?relay=` URI hints onto custom relays with `n0` DNS/Pkarr off and bearer token guard `p2pRelayAuthToken`, supporting `p2pRelayUrls` for managed `iroh-relay` pools, and rejecting `p2pApiSecret` in the browser so API secrets are never embedded in client JS), packs initial `preamble || msg1` bytes into `Dial.init_frame` across relayed `pair`, `connect`, `connectV2`, and `enroll` calls when `challenge.fast_open === true` (skipping redundant post-`ready` sends when `stream.fastOpenSent` is `true` and falling back cleanly on older relays), serializes cipher-state advances and multi-chunk frame flushes via `#sendChain` (`#recvChain` for `pollEvent`) while keeping `stream.recv()` unblocked, prefers `onPersistRosterBytes` over string `onPersistRoster` when both are provided (zeroizing the `Uint8Array` after `await`) and rolls back roster changes on persistence failure (failing closed if revocation persistence fails), guards `TendrilWebClient.free()` by aborting active sessions and deferring WASM `free()` until in-flight holds release, zeroizes `Uint8Array` secret inputs in `finally` blocks, exports top-level `@tendril-sdk/web` helpers (`canonicalRelayHost`, `computeRelayAuthHmacB64`, `deriveV2RelayDial`, `v2EpochWithinSkew`, `dialBrokerStream`, `validateBrokerWsUrl`, `createIndexedDbVault`, `openTendrilVault`), and exposes `TendrilWebClient.{pairV2, connectV2, mintRelayTicket, addTrustAnchor, revokeTrustAnchor, mintEnrollmentToken, enroll}` and `TendrilWebSession.ping(cookie?)` (wrapping `WasmV2SessionInitiator::send_ping`) for Wire `0x02` and browser M2M workflows.
- **Groups (member side only).** `TendrilWebClient.create` accepts `groupBookJson` / `groupBookBytes` and `onPersistGroupBook` / `onPersistGroupBookBytes` (same persistence and rollback pattern as the roster). The client exposes `exportGroupBookJson`, `exportGroupBookBytes`, `groupIds`, `groupMembers`, `groupAuthorizePeer`, `ingestGroupManifest` (a manifest or a `group_manifest_unverified` event plus the authenticated session it arrived on), and `openGroup`. `openGroup` returns `TendrilWebGroup` (`bindings/web/src/group.js`) for a group whose manifest is already ingested: `attach` / `detach` register established sessions, `handleSessionEvent` routes events the app polled itself, `broadcast(data, requiredCap?)` fans out over those sessions (or over sessions supplied lazily by `sessionFor`) and returns `{delivered, offline, failed}`, and `on` / `pollEvent` surface `app_data`, `manifest_updated`, `member_joined`, `member_revoked`, and `audit` events with the same JSON as the native bindings. Queued `audit` events also carry `count` and are coalesced per authenticated sender, outcome (allow or deny), and cap (the entry holds the latest audit in full, a denial is never merged into an allow, and one sender holds at most 8 distinct queued entries, so a ninth distinct cap is dropped from the queue and never merged into another), audits never use the control-event reserve, listeners still see every audit, `close()` stops queue and waiter delivery (a callback already being dispatched still finishes), and an audit with no queued entry is dropped from the queue (not from listeners) when the queue is at the data threshold or the sender is at its entry limit. The browser can join a group and send, but it has no listener, no root-side create, add, remove, or `sync`, and no group hub; recipients are re-checked against the WASM group book immediately before each send. Persist the group book in the same vault as the identity and roster, because it holds rendezvous keys. See [Small peer mesh groups](../design/groups.md).
- **Pairing URIs and routes.** `TendrilWebClient.pair` races its browser-compatible hints using `WasmPathPlanner` (`250 ms` Happy Eyeballs stagger, `500 ms` P2P cold-start hold delay, immediate advance on failure) up to `msg2` verification behind a single-winner latch, aborts losing attempts, verifies `rp` and `rs` before committing `msg3` on exactly one stream, and stores routes under `routePolicy` (`allSigned`, the default, `committedOnly` or `none`) and `saveRoute`. `TendrilWebClient.pairV2` remains strictly sequential across candidates. Hints the browser cannot dial are skipped and reported in `skipped` with a reason (`browser_unsupported`, `ipc_from_uri`, `insecure_ws`, and others): `wss://` and `broker+wss://` are kept, `ws://` and `broker+ws://` only on loopback or with `allowInsecureWs`, `iroh://` only when the opt-in `pkg-p2p` module loads (`hasP2pSupport()`, `relay=` stripped, dialed without address lookup through `p2pRelayUrls` or the Default relay map), and `direct:`, `overlay://`, and every `/v2/relay` hint are skipped. A malformed code is rejected before any dial and a two-group LAN code fails without dialing, since no browser candidate is a LAN path. A result carries `route_check`, `routes_persisted`, `routes_reason`, `route`, `skipped` and `failures`; a failed attempt throws a `TendrilAttemptError` with `committed: true` once a `msg3` byte may have been written.
- **Endpoint-free connect.** `connect` and `connectV2` with neither `endpoint` nor `relayUrl` dial the peer's stored routes (plus a signed `recoveryUri`'s hints) concurrently via the shared `WasmPathPlanner` Happy Eyeballs runner (`250 ms` stagger, `500 ms` P2P cold-start hold delay, `/v2/relay` before `/v1/relay`, numeric hosts before DNS hosts, `AbortController` teardown of losing attempts) using each candidate's own roster clone, then reconcile rotation and CRL evidence once, run the final authorization check and apply recovery routes only if it passes. `replaceRoutes` approves an older recovery URI. The session sends `route_seq` when the policy is `allSigned` and applies host route sets with the same rate limit as native clients (`session.lastRouteSet`, `session.recoveryRoutes`). Stored `/v2/relay` routes appear only through `connectV2`. Route management: `getPeer(id).routes`, `peerRoutes`, `setPeerRoutes`, `clearPeerRoutes` and `applyRouteUri` (offline, no code used). `relayAuthOrigins` limits where `relayAuthTicket` and `relayAuthSecret` are attached; the explicit `relayUrl` of a call is always allowed.
- **Errors, locking and explicit endpoints.**
  - Errors carry a stable `code` property. A core failure has the snake-case name of its core error (`host_key_unverified`, `peer_revoked`, `rotation_fork_detected`, `invalid_pairing_uri`, `pairing_code_invalid`, ...); an argument or state error of the WASM layer has `error`; the SDK adds `relay_auth_unconfigured` for a relay that demands credentials the client was not configured to send. Candidate errors are ranked by `code`, never by message text, and `TendrilAttemptError.code` is the code of the error that won the ranking. Messages never echo input: a hint in an error list is shown as `scheme://host[:port]` or `<redacted>`, and route and URI errors name only the failure.
  - `clearPeerRoutes(peerId, source?)` removes `operator` routes when `source` is omitted. Pass `signed`, `committed` or `all` to remove others.
  - If authenticated evidence (a key rotation, a revocation list, or the revocation a rotation fork causes, learned during a handshake or a connect) cannot be persisted, the client locks: that call fails with the persistence error as `cause`, every open session fails and closes (its next call rejects with `session locked after roster persistence failure`), and every later roster operation and group call rejects with `client locked after roster persistence failure`. Create a new client from the last persisted roster. A session that cannot persist its own roster update closes the same way (`session locked after roster persistence failure`).
  - `pair` and `pairV2` reject an explicit `endpoint` or `relayUrl` that is a `/v2/relay` URL with `/v2/relay is not used for pairing; pair over another route, then use connectV2`, before any dial. `connectV2` accepts it. A URI's own `/v2/relay` hint is skipped as `relay_v2_not_authorized`.
  - `skipped` reasons include `insecure_ws` (a `ws://` hint off loopback without `allowInsecureWs`), `p2p_feature_disabled` (an `iroh://` hint without the `pkg-p2p` module), `blocked_address`, `invalid`, `ipc_from_uri`, `relay_v2_not_authorized` and `browser_unsupported`.
- **Roster lock.** Every roster mutation (pairing persistence, session roster updates, route announcements, route setter calls, group ingest steps that touch the roster) runs in one FIFO critical section that includes the persist callback, so rollback is correct. No socket I/O or group hook runs inside it. A client method called from `onPersistRoster` or `onPersistRosterBytes` is queued behind the current section: the callback may start such a call without awaiting it, and must not await it, which would wait for its own section to end (a warning is logged after 5 s). Use one `TendrilWebClient` per roster storage; cross-tab coordination is not provided.
- `bindings/web/src/vault.js` exports `createIndexedDbVault` (aliased as `openTendrilVault`), a reusable WebCrypto AES-256-GCM IndexedDB vault for sealing identity and roster bytes/strings under a non-extractable AES-256-GCM key.
- `bindings/web/src/worker.js` and `computeCodeMacWorker` (`code: string | Uint8Array`, `handshakeHash`, `{ timeoutMs }`) move Argon2id pairing-code proof computation off the UI thread, transferring and zeroing `Uint8Array` secret code inputs and terminating hung or unserializable workers on timeout or `messageerror`; `computeCodeMacBytes` exposes the synchronous zeroizing path directly.
- `bindings/web/demo/` provides an interactive pairing/session web page supporting `wss://.../v1/relay`, `wss://.../v2/relay` proxy routing, and `iroh://...` endpoints, serving strict `Content-Security-Policy` (`frame-ancestors 'none'`, `'wasm-unsafe-eval'`), `X-Frame-Options: DENY`, and `Referrer-Policy: no-referrer` headers, allowlisting static `/demo/` assets (`404` on `/demo/server.mjs`), enforcing RFC 6455 WebSocket upgrade header/timeout validation in `server.mjs`, enforcing `/demo-config.json` precedence + fragment-only `#code=` / `#uri=` secrets (ignoring and scrubbing query-string secrets with a warning) + a log redaction toggle (default ON) + third-party override warnings in `app.js`, and sealing identity/roster bytes in IndexedDB (`tendril-demo-vault-v1`) via `createIndexedDbVault`.
- `bindings/web/test/group.test.mjs`, `bindings/web/test/security.test.mjs`, and `bindings/web/test/browser_e2e.mjs` (all run by `make bindings/web`) verify URL/queue/concurrency/persistence/lifecycle hardening, zeroizing worker MAC helpers, M2M enrollment/replay/anchor-revocation flows over live WSS relay, `spec/vectors/`, `parseP2pEndpoint` validation, and live headless Chrome `Noise_XXhfs` relay flows against `tendril-relay` and `tendril-conformance-peer` (plus live `iroh://` browser-to-host E2E over n0 public relays when `TENDRIL_WEB_P2P_LIVE=1`).

## Android Kotlin JNI (`bindings/kotlin`)

- `bindings/kotlin/jni/tendril_jni.c` bridges `dev.tendril.TendrilNative` methods (including `endpointAddTrustAnchor`, `endpointRevokeTrustAnchor`, `endpointMintEnrollmentToken`, and `endpointEnrollInitiate`) to `crates/tendril-ffi/include/tendril.h`, converts standard UTF-8 <-> UTF-16 directly (preserving non-BMP characters and formatting dynamic full-length FFI error messages), rejects embedded NUL bytes in string inputs, validates non-negative integer inputs and `0..=65535` close codes, maps `TENDRIL_WOULD_BLOCK` and `TENDRIL_EOF` into JSON status sentinels, and frees all returned C strings with `tendril_string_free`.
- `TendrilEndpoint` and `TendrilSession` in `TendrilClient.kt` expose full M2M enrollment (`addTrustAnchor`, `revokeTrustAnchor`, `mintEnrollmentToken`, `enrollInitiate`), authenticated peer lookup (`TendrilSession.peerId()` via `TendrilNative.sessionPeerId`), and implement `java.io.Closeable` with `ReentrantReadWriteLock` handle synchronization, calling `tendril_endpoint_close` / `tendril_session_shutdown` outside exclusive native free so concurrent `close()` calls unblock and serialize safely against active FFI polls or sends.
- `KeystoreStateCipher.kt` (`SealedStateStore`) seals and unseals the identity JSON (`identity.sealed`, temp file synced before the atomic move) via an `AndroidKeyStore` AES-256-GCM key (`12`-byte random IV prefix, version `0x01`, domain AAD, verifying Keystore key presence). `TendrilEndpoint.create(stateDir)` passes it to `tendril_endpoint_new_sealed`, and the runtime persists the roster and group book itself in `rt-roster.sealed` and `rt-groups.sealed` (see [Sealed local state](../design/groups.md#sealed-local-state)); the binding no longer writes the roster. Identity bootstrap runs under an exclusive lock on `.identity.lock` (a per-directory JVM monitor plus a `FileChannel` lock), so concurrent first opens share one identity, and a generated identity is saved before any runtime state exists. A legacy `roster.sealed` is read only when no runtime state exists, seeds the runtime roster once, and is then deleted; a leftover is deleted unread. `AndroidManifest.xml` disables cloud/ADB backups (`android:allowBackup="false"`, `tendril_backup_rules.xml`, `tendril_data_extraction_rules.xml`). On Android the state store takes its `flock` through `rustix`, since std `File::lock` is unsupported there.
- Group APIs (`groupCreate`, `groupAddMember`, `groupRemoveMember`, `groupIngestManifest`, `openGroup`, and `TendrilGroup` with `broadcast`, `sync`, `localEndpoint`, `pollEvent`, `authorizePeer`) map to the `tendril_group_*` C ABI through `dev.tendril.TendrilNative`; see [FFI ABI and bindings](ffi-and-bindings.md). Endpoints from `TendrilEndpoint.create(stateDir)` host groups; only `create(stateDir = null)` refuses them with an `IllegalStateException` reading "tendril ffi error (-1): groups require a state directory endpoint". The Kotlin group sources are unverified on Linux CI.
- Pairing URIs and routes: `TendrilEndpoint` wraps the route C ABI (see [Pairing URIs and routes](ffi-and-bindings.md#pairing-uris-and-routes)) as `issuePairingUri`, `pairUri`, `pairV2Uri`, `connectWithOptions` (recovery URI, `replaceRoutes`), `setPeerRoutes`, `peerRoutes`, `clearPeerRoutes`, `applyRouteUri`, `refreshRoutes` and `configureRoutes` (`relayAuthOrigins`, `advertise`, `routePolicy`, `signRoutes`, `advertisedEndpoints`). `connect` and `connectV2` take a null `endpoint` to dial the peer's stored routes. `connectWithOptions` treats a blank `grantJson` as no grant and throws `IllegalArgumentException` for text that is not exactly one strictly valid JSON object (no sibling keys, trailing commas, comments or control characters); the native parser stays authoritative for the grant's content. `configureRoutes` merges its keys into the last full transport configuration the binding sent (a binding-held cache), so relay tickets and other keys survive; `configureTransportsJson` replaces the whole configuration and the cache, which changes only after the native call succeeds. The cache is a plain JVM copy of the configuration, secrets included, that `close()` clears; it cannot be zeroized. Results are the C ABI JSON strings.
- `TendrilForegroundService.kt` maintains a `dataSync` foreground notification and monitors `ConnectivityManager.registerDefaultNetworkCallback` across Wi-Fi and cellular handoffs. It also registers an all-networks callback (`NetworkRequest` without `NET_CAPABILITY_NOT_VPN`, so VPN networks are included) that keeps a `Network` to `LinkProperties` and `NetworkCapabilities` map. `LocalBinder.attachEndpoint(endpoint)` seeds the map from `ConnectivityManager.allNetworks` (the callback is registered first, seeding and callbacks mutate the map under one lock, callback values win, and a denied enumeration leaves the map unchanged) and refreshes before the first pairing URI is issued; every map change then passes the whole map to `refreshRoutes(snapshot)` (transports from `NetworkCapabilities.hasTransport`), and a 60 s timer calls `refreshRoutes(null)`, which reuses the retained snapshot. The runtime applies the 30 s empty-snapshot debounce, so a lost last network retires its addresses without a transient empty set.
- `bindings/kotlin/test/TendrilJniConformanceTest.java` validates all four helper vectors (`fingerprints.json`, `pairing_mac.json`, `rotation.json`, `grants.json`), NUL/close hardening, bidirectional live interop against `tendril-conformance-peer`, M2M enrollment/replay/anchor-revocation, the group mesh, and a sealed endpoint hosting a group across restart (`verifySealedGroupState`) on host Linux JVM (`make bindings/jni` tests the C JNI bridge and Java declarations; compiling `.kt` Android sources requires Gradle and the Android SDK). `verifyPairingUriRoutes` repeats the pairing URI flow on the host JVM: signed issuance, Wire v1 and v2 URI pairing, endpoint-free connect, the route setter, offline apply, recovery URIs, snapshot refresh with delivery of a route set to a live session, and a sealed route sequence across close and reopen.
- `crates/tendril-ffi/build.rs` sets `DT_SONAME=libtendril_ffi.so` and `-Wl,-z,max-page-size=16384` (16 KB ELF page alignment, matched in `bindings/kotlin/jni/CMakeLists.txt`), and `TendrilAndroidSmokeTest` (20/20 instrumentation tests, adding `grantOptionRejectsInjectionAndBlank`, `transportConfigCacheMergesAndCachesOnlyAfterSuccess`, `configureRoutesKeepsRelayTicket`, `networkMapSeedingKeepsCallbackStateAndSurvivesDeniedEnumeration`, `runAllGuardedRunsEveryStep`, `signedPairingPersistsAllRoutes`, `networkCallbackRefreshesRoutes`, `multiNetworkSnapshot`, `addressChangePropagatesAndReconnects`, `sealedSeqSurvivesRestart`, `builderUriIsUriParseFixpoint`, `scannerPassthrough` (ZXing render at ECC M, ML Kit decode, byte equality, verified route check) and `serviceSeedsHostFromRealNetworks`; the original 7: `KeystoreStateCipher` AES-GCM AAD binding, `TendrilEndpoint` sealed identity persistence plus M2M enrollment token minting, `configureTransportsJson` plus `RelayTicket` minting, `sealedEndpointHostsGroupAcrossRestart` (two sealed endpoints enroll, create, add, ingest, broadcast, recreate the member, broadcast again; a tampered `rt-groups.sealed` makes `create` throw), `sealedEndpointMigratesLegacyRosterOnce` (a nonempty legacy roster migrates and is deleted; a corrupt leftover is deleted unread), `concurrentFirstOpensShareOneIdentity`, and `groupApiRefusesWithoutStateDir`) passed on a physical `arm64-v8a` Android 15 device via `bindings/kotlin/scripts/adb-smoke.sh` on 2026-11-23.

## Apple Swift (`bindings/swift`)

- `bindings/swift/Package.swift` declares `CTendril` (`module.modulemap` + `shim.h` referencing `crates/tendril-ffi/include/tendril.h`), the `Tendril` wrapper module (`TendrilCrypto`, `TendrilEndpoint` including `addTrustAnchor`, `revokeTrustAnchor`, `mintEnrollmentToken`, and `enrollInitiate`, plus `TendrilSession` including `peerId()`, validating strings against embedded NUL bytes and using `NSCondition` active-call refcounting with `tendril_endpoint_close`/`tendril_session_shutdown`), `TendrilKeychainStore` (`SealedSwiftStateStore` handling `errSecDuplicateItem`, key buffer zeroization, version `0x01` + domain AAD `CryptoKit` AES-GCM sealing of the identity, with the temp file synced before the move and the state directory excluded from backups), and `TendrilTests` (offline vectors, fork rejection, local endpoint lifecycle, and M2M enrollment/replay checks).
- Group APIs (`groupCreate`, `groupAddMember`, `groupRemoveMember`, `groupIngestManifest`, `openGroup`, and `TendrilGroup` with `broadcast`, `sync`, `localEndpoint`, `pollEvent`, `authorizePeer`) wrap the same `tendril_group_*` C ABI; see [FFI ABI and bindings](ffi-and-bindings.md). On Apple platforms `TendrilEndpoint(stateDir:)` keeps the identity sealed by `TendrilKeychainStore` and opens the endpoint with `tendril_endpoint_new_sealed`, so the runtime persists roster and group state in `rt-roster.sealed` and `rt-groups.sealed` and the endpoint hosts groups; the binding no longer writes the roster, and a legacy `roster.sealed` seeds it once and is then deleted. Identity bootstrap holds an `flock` on `.identity.lock` per call, as on Android. Endpoints without a `stateDir` throw `TendrilError.ffi` with code `-1` and the message "groups require a state directory endpoint". The Swift group sources are unverified on Linux CI.
- Pairing URIs and routes: `TendrilEndpoint` wraps the route C calls (`issuePairingUri`, `pairUri`, `pairV2Uri`, `connectWithOptions`, `setPeerRoutes`, `peerRoutes`, `clearPeerRoutes`, `applyRouteUri`, `refreshRoutes`, `configureRoutes`; see [Pairing URIs and routes](ffi-and-bindings.md#pairing-uris-and-routes)). `connect` and `connectV2` take an optional `endpoint` and dial the stored routes without one. `configureRoutes` merges only the arguments passed into the last full transport configuration the binding sent (`configureTransportsJSON` replaces it), so relay credentials, P2P and wake keys stay; a failed native call leaves the cached configuration unchanged. `startPathMonitoring()` runs an `NWPathMonitor` whose path updates call `refreshRoutes()` (native interface enumeration), so a host's announced routes follow its network; `close()` stops it.
- Verification note: `swift test` (13/13 tests, including `keychainSealedEndpointHostsGroupAcrossRestart`, `keychainSealedEndpointMigratesLegacyRosterOnce`, and `keychainConcurrentFirstOpensShareOneIdentity` through the `customKeyProvider` seam and the group refusal without a state directory; verified 2026-11-23) and `aarch64-apple-darwin` (macOS arm64) release builds pass on macOS arm64 with Swift 6.4.2 (verified 2026-11-22); with full `Xcode.app` (`iPhoneOS` and `iPhoneSimulator` SDKs), `aarch64-apple-ios`, `aarch64-apple-ios-sim`, `TendrilFFI.xcframework` (3 `arm64` slices), and `xcodebuild -scheme Tendril` builds for `generic/platform=iOS` and `generic/platform=iOS Simulator` all pass.
- Swift test prerequisites: the full `Xcode.app` toolchain (`DEVELOPER_DIR=/Applications/Xcode.app/Contents/Developer`; Command Line Tools alone cannot build Swift Testing), a release `tendril-ffi` build (`cargo build --release -p tendril-ffi --lib`; a debug build overflows the test thread stack in ML-DSA key generation, so clean `.build` after switching), and debug `tendril-relay` and `tendril-conformance-peer` binaries. Keychain tests skip themselves when no login Keychain is available, for example over ssh.

## Gate #9 pairing and reconnect baselines

### Desktop headless Chrome WebSocket relay (post-`ADR 0004` `Noise_XXhfs`)

Measured in headless desktop Google Chrome against `tendril-conformance-peer` over a loopback `tendril-relay` (`Noise_XXhfs_25519+MLKEM768_ChaChaPoly_SHA256`, `1216 B` `msg1`, and `3373 B` hybrid `Ed25519 + ML-DSA-65` signatures):

- **Remote pairing (`TendrilWebClient.pair`):** `269.4 ms` end-to-end (includes `Noise_XXhfs` `pair` handshake and Argon2id `code_mac`).
- **Authenticated session connect (`TendrilWebClient.connect`):** `18.0 ms` initial `Noise_XXhfs` handshake over loopback relay (`14.6 ms` repeat connect).
- **Encrypted control and data round-trip:** `25.5 ms` encrypted `0x05 PING` -> `0x06 PONG` RTT, `0.2 ms` client `0x04 REKEY` dispatch, and verified `21`-byte plaintext delivery on the Rust conformance peer.

These desktop headless figures are local loopback baselines and are not directly comparable to WAN physical-phone latencies.

### Historical pre-`ADR 0004` physical-phone baselines

> [!NOTE]
> The two physical-phone subsections below are **historical pre-`ADR 0004` baselines** measured under classical `Noise_XX` before `1216 B` `Noise_XXhfs` `msg1` and `3373 B` hybrid `Ed25519 + ML-DSA-65` signatures landed in wire v1. Physical-phone re-measurement under `Noise_XXhfs` is pending.

#### WebSocket relay baseline (physical phone, pre-`ADR 0004` classical `Noise_XX`)

Observed between a physical mobile browser and the desktop Rust `tendril` CLI host over the WebSocket relay demo (`< 30 s` pairing target):

- **Remote pairing:** `0.59 s` end-to-end with verified 16-character SAS match and host `tendril confirm`.
- **Authenticated session connect:** `332.1 ms` initial pre-`ADR 0004` classical `Noise_XX` handshake over relay (`164.5 ms` repeat connect).
- **Encrypted control and data round-trip:** `27 ms` encrypted `0x05 PING` -> `0x06 PONG`, followed by `0x04 REKEY` and verified plaintext delivery (`21` bytes) decoded on the Rust host.
- **Disconnect and reconnect recovery:** Re-established authenticated relay sessions in `526.5 ms`, `520.4 ms`, and `418.0 ms` across manual reconnect and connectivity restoration tests.

#### Zero-setup `iroh://` baseline (physical phone, Tailscale OFF, pre-`ADR 0004` classical `Noise_XX`)

Observed between a physical mobile browser (Tailscale OFF, zero self-hosted Tendril relay) and `tendril serve --p2p --issue-code remote` over bare `iroh://` routed via public `n0` relay (`euc1-1.relay.n0.iroh.link.`):

- **Warm remote pairing:** `0.87 s` with verified 16-character SAS match and host `tendril confirm` (a cold first tap timed out while downloading the uncompressed `3.93 MiB` `pkg-p2p` bundle inside the shared `15 s` timeout, motivating `initTendrilP2p()` pre-warming and gzip compression in `demo/server.mjs`).
- **Authenticated session connect (`provider: P2p`):** `634.9 ms` initial pre-`ADR 0004` classical `Noise_XX` QUIC establish.
- **Encrypted control and data round-trip:** `63 ms`, `67 ms`, and post-rekey `69 ms` `0x05 PING` -> `0x06 PONG` RTTs, followed by `0x04 REKEY` and `21`-byte plaintext verified on the Rust host.
- **Disconnect and reconnect recovery:** Clean session close (`code=1000`, `reason="reconnect"`) and re-establishment in `392.9 ms` over `provider: P2p`.
